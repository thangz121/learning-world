## 3. Bugs discovered (observation set)

**J1 — P1 — Startup mic offer card swallows world clicks.**
Evidence: `[Probe] PRE p=(870,348) overUi=True ui=[Body|OfferPanel]`,
`POST hasDest=False`. Fix: card image + title/body/status texts are
`raycastTarget=false` (buttons stay interactive) in `MicSetupDialog` and
`DependencySetupDialog`.

**J2 — P1 — MathScene return gate can never fire.**
Evidence: post-fix journey 3: player stood 0.82 m from the arch, `nav=math`,
no WorldChanged. Root cause: `MathWorldBuilder.BindReturnGate` bound
`SubjectIds.Main`, but `SubjectGate`'s return branch fires only when
`nav.Current == target` (Math ≠ Main). Fix: bind the SUBJECT id (same as the
spatial return arches). Pin: CT-P43K.

**J3 — P1 — Main navmesh removed while in a subject → return warp fails.**
Evidence: journey 4 `[MarketBootstrap] Return warp failed; player stays.`,
player left at Math coordinates (60.3,10.7) after the Math scene unloaded.
Root cause: `DeactivateMainPresentation()` disables the MarketBuilder root,
which contains the Main `NavMeshSurface`; `NavMeshSurface.OnDisable()` calls
`RemoveData()` (package source verified), so `WarpTo`'s `NavMesh.SamplePosition`
found nothing at Main. Fix: the Main NavMesh GO is moved into `PersistentCore`
in `MarketBuilder.BuildPersistentCore` (persistent core service, like
Player/Camera/HUD).

**J4 — P1/P2 — Re-entry blocked: return warp landed inside the gate radius.**
Evidence: journey 5: after return the player sat at the gate mouth (0.63 m);
the entry gate never re-fired (nav stayed main). Root cause: the return warp
reused the cached pre-entry position (on the gate mouth) while
`SubjectGate._wasInside` was still latched true from the first entry → no
rising edge. Fix: when the cached return spot is within 2.2 m of the gate,
land 3 m hub-side instead (`[MarketBootstrap] Return warp -> (7.7,0.0,-2.8)`).

**J5 — P1 — Mid-quest re-entry made the bring objective impossible.**
Code evidence: `MathHostPresenter.IsFindDone()`/`CompleteBring()` required
`_questStarted`, which a fresh presenter instance never receives on re-entry
(no QuestStartedEvent replay). Fix: find-done/bring are quest-STATE driven
(`ObjectiveIndex >= 1 && !Completed`). Pins: CT-P40E.

**J6 — P2 — Reward blooms lost on re-entry after completion.**
`MathBloomDisplay` only reacted to the event; a fresh scene load after
completion showed a bare garden. Fix: `Build(bus, quests)` adopts a completed
quest (idempotent apply). Pin: CT-P40F.

**J7 — P2 — Reward cube reappeared on re-entry after completion.**
Evidence: journey 6 re-entry `token=InWorld` (post-completion). Fix:
`MathTokenCarry.Build` adopts `Consumed` (cube + hand token hidden).
Pin: CT-P40G.

**J8 — P2 — Math NavMesh bake collected every loaded scene.**
Evidence: the Math bake log listed Main-only meshes (LwGrass/Flowers/Bush_2);
overlapping navmesh data over Main + Main player/NPCs baked as obstacles.
Fix: the surface lives ON the MathWorld root with `CollectObjects.Children`
(bake only Math geometry). Main's own navmesh now persists independently (J3).
